# Java 场景设计实验室

可执行代码位于仓库根目录的 `scenario-lab/`，与本文档站点分开管理。每个子目录是独立的 Spring Boot 工程，使用 JDK 17、Spring JDBC 和 H2，不需要另行部署数据库。

| 工程 | 实验重点 |
| --- | --- |
| feed | 写扩散、读扩散、游标分页及陈旧索引权限过滤 |
| seckill | 并发条件扣库、一人一单、异常事务回滚 |
| payment | 重复回调、账务与 outbox、退款额度及请求幂等 |
| qrlogin | 扫码确认状态、浏览器绑定、一次性兑换 |
| shortlink | 短码碰撞重试、安全协议及过期 |
| orderexpiry | 支付和关单竞争、晚到支付生成退款任务 |
| redpacket | 金额守恒、一人一次、奖品防超发 |
| im | 消息幂等、会话序号与按游标补拉 |
| ranking | 事件去重、绝对分数和版本保护 |
| scheduler | 租约争抢、到期重领、fencing token |
| cache | 旧快照回填、持久版本栅栏 |

从仓库根目录运行：

```powershell
.\scenario-lab\run.ps1 -Action verify -Offline
.\scenario-lab\run.ps1 -Module seckill -Action run -Port 8080 -Offline
Invoke-RestMethod -Method Post 'http://localhost:8080/api/buy?user=101'
```

`test` 运行规则单元测试，`verify` 还运行真实 Spring + H2 事务、并发以及 MockMvc HTTP 集成测试。脚本默认使用本机 JDK 17 路径，可以通过 `-JdkHome` 覆盖；依赖未缓存时去掉 `-Offline`。每个模块都有建表 SQL、启动类、业务服务和测试，详细命令、覆盖范围和模拟边界参见仓库内 `scenario-lab/README.md`。

这些实验演示设计的核心机制；Redis、MQ、渠道、真实 WebSocket、分片和跨节点故障未部署。缓存用同库表模拟版本栅栏，其事务保证不能直接推广到 Redis/DB；H2 也不能代替目标数据库的锁行为与性能测试。
